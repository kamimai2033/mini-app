# 更新計画

未実装の機能追加・更改の計画書を置く。実装後は、確定した内容を`docs/*-integration.md`などの連携仕様へ移し、この一覧の状態を「実装済み」に変える。計画書は現行リリースへの実装確約ではない。

| 計画 | 対象版 | 状態 | 概要 |
| --- | --- | --- | --- |
| [本棚・図書館](library-integration.md) | 1.13.0（予定） | 仕様案 | 蔵書・借用中の本・置き場所の管理。連続スキャン、書名検索、シリーズ、読書状態。NASのSQLiteを正本とし、独立したスプレッドシートへミラーする。 |

2.xに向けた共通基盤の更改案は[2.xに向けた更改案](../roadmap-2x.md)を参照する。

## 計画書の書き方

1. 冒頭に作成日・状態・対象版を書く。
2. 「要点」の表で、決まったことを1画面で読めるようにする。
3. 本文は画面 → 操作の流れ → データ → API → 同期・バックアップ → 検証 → 段階と未決事項の順に書く。
4. 段階はチェックリストにし、進捗に合わせて更新する。
