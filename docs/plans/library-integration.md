# 本棚・図書館の連携（仕様案）

作成：2026-11-24／状態：仕様案・未実装／対象：v1.13.0（予定）

## 要点

| 項目 | 決定内容 |
| --- | --- |
| 画面 | 生活 → 本棚・図書館。画面内メニューは蔵書管理／借用管理／置場管理／共通設定。4画面を一体で作り、同時に出す。 |
| 正本とバックアップ | NASのSQLiteが正本。独立したスプレッドシートへ片方向にミラーし、DB破損時の復旧元にする。 |
| 登録 | 連続スキャン（ISBN）、書名検索（国立国会図書館サーチ中心）、手入力。iPhoneの「テキストをスキャン」と奥付の文字認識で入力を補助する。 |
| 同人誌 | ISBNを必須にしない。国立国会図書館の書誌IDを識別子として併用する。 |
| 借用 | 借りた先は自由入力。期間は2週間／1か月／日付指定。期限の近い順に表示し、期限切れ・3日以内を強調する。 |
| 置き場所 | 入れ子を自由に作れる。箱ごとの移動、移動スキャン、一括移動に対応する。 |
| その他 | シリーズ・巻、読書状態、メモ、入手情報（任意）、手放した本の記録、重複の警告、表紙の一括表示切替え。 |
| 対象外 | 他人への貸出、ストアの電子書籍、複数利用者、外部への期限通知。 |

蔵書と借用中の本を一つの機能で管理する。蔵書・借用・置き場所の正本はNASのSQLiteに置く。独立したGoogleスプレッドシートへ片方向にミラーする。画面は他機能と同じくHTML／CSS／ES Modulesで作り、日用品・家計簿と同じ送信待ち・再送の方式を使う。

## 1. 範囲

| 対象 | 対象外 |
| --- | --- |
| 紙の蔵書、同人誌の電子版の所有記録 | ストアで購入する電子書籍 |
| 図書館などから借りた本の返却期限管理 | 他人への貸出 |
| 置き場所（入れ子・移動・一括移動） | 複数利用者・家族共有（本人用キー1本） |
| 書誌の自動取得（ISBN・書名検索）、シリーズ、読書状態、メモ | 返却期限の外部通知（画面内の強調表示のみ） |
| 表紙の縮小画像（一括で表示・非表示を切り替え） | projectLivreとの照合（§10、将来） |

## 2. 画面

### 2.1 階層と名称

[生活メニューの画面仕様](../life-navigation.md)の文字数規則に従う。

| 階層 | 項目・見出し | 文字数 |
| --- | --- | --- |
| 展開メニュー（生活） | 既存5項目の末尾に「本棚・図書館」を追加 | 6 |
| 機能の見出し | 本棚・図書館 | 6 |
| 画面内メニュー | 蔵書管理／借用管理／置場管理／共通設定 | 各4 |

初回は「蔵書管理」を表示する。画面内メニューを切り替えても、見出し・4項目・送信待ち・入力中の下書きを維持する。4画面は一つのモジュール・一つのShadow DOMで構成し、同時にリリースする（§11）。

### 2.2 蔵書管理

- 一覧：シリーズごとにまとめる表示と、1冊ずつ並べる表示を切り替える。既定はシリーズごと。
- 検索：書名・著者・サークル・出版者・シリーズ名・メモを対象にする。
- 絞込み：読書状態、置き場所（配下を含む）、形態（紙／電子）、「手放した本を含む」。
- 登録：連続スキャン（§3.1）、書名検索（§3.2）、手入力（§3.3）。
- 詳細：書誌の確認・修正、シリーズと巻、置き場所、読書状態、入手情報、メモ。「手放した」操作と取消し。
- 重複の警告：§3.4のとおり。

### 2.3 借用管理

- 一覧：未返却の本を返却期限の近い順に表示する。期限切れと残り3日以内を強調する（日数は設定で変更可）。
- 登録：先に「借りた先」と「貸出期間」を決め、連続スキャン・書名検索・手入力で追加する。
  - 借りた先：自由入力。過去の入力を候補に出す。
  - 貸出期間：「2週間／1か月／日付を指定」から選ぶ。同じ借りた先は前回の期間を初期値にする。
- 返却期限：借りた日（既定は当日）＋期間で決めた日付を保存する。日付だけで扱い、Asia/Tokyoで判定する。
- 操作：返却（返却日を記録）、延長（新しい期限を記録し延長回数を加算）、期限・メモの修正。
- 履歴：返却済みの記録は削除せず、「返却済みを表示」で閲覧する。
- 読書状態とメモは蔵書と同じ項目を持つ。

### 2.4 置場管理

- 置き場所は自由に入れ子にできる（例：部屋＞本棚＞段、押入れ＞箱3）。階層の深さは問わない。
- 作成・名称変更・親の付替え（箱ごとの移動）・統合を行う。削除は空の置き場所に限る。
- 各置き場所に、配下を含む冊数と一覧を表示する。
- 移動スキャン：移動先を選んで連続スキャンし、読んだ蔵書をまとめて移す。
- 一括移動：一覧でチェックした蔵書（バーコードのない同人誌を含む）を移す。
- 「場所未設定」を正式な状態として扱い、登録や片付けの途中でも保存できるようにする。

### 2.5 共通設定

- 接続先（HTTPSのOrigin）と本人用アクセスキー。キーはメモリー内だけに保持する。
- 到達状態、最終同期時刻、送信待ちの一覧と取消し、書誌未取得の件数。
- 表紙の表示：全体で一括してオン・オフする（既定はオフ）。
- 文字認識の準備状態（既存OCRと共用）。
- Sheetsへの反映状況（NASからの報告値。最終反映時刻・未反映件数）。
- 期限の強調日数。

## 3. 登録の流れ

### 3.1 連続スキャン

`janScanner.js`の`startScan`は、停止するまで約300msごとに読取り結果を返す。日用品は1件で停止しているが、本機能は停止せずに読み続け、画面側で次の処理を行う。

1. 事前条件を決める。蔵書は置き場所・シリーズ・形態、借用は借りた先・貸出期間。
2. 読み取ったコードを判定する。
   - 978／979で始まる13桁でチェックディジットが正しいものはISBNとして採用する。
   - 192／191で始まるコード（書籍JANの下段）は無視する。
   - それ以外のEANは「ISBNではありません」と一覧に出し、書名検索へ切り替えられるようにする。
3. 同じコードを5秒以内に読んだ場合は無視する。採用時に短い音を鳴らす。
4. 読取済み一覧に追加する。到達できる場合はNASへ書誌を問い合わせ、届いた順に書名を埋める。
5. 一覧では、不要な行の削除、候補の選び直し、「書名で検索」行の追加ができる。
6. 「まとめて登録」で、各行を1件ずつのUUID付き操作として送信待ちに保存してから送信する。

NASに到達できない場合は、ISBNと事前条件だけで登録し、「書誌未取得」とする。返却期限は端末内で確定する。再接続後に書誌を埋める。外出先ではTailscale経由の接続を想定するが、圏外でも登録は止めない。

### 3.2 書名検索

ISBNのない同人誌や、図書館のラベルでバーコードが隠れた本に使う。

- 入力欄に書名・著者・サークル名を入れ、NAS経由で検索する（§5）。候補から選ぶと書誌IDとともに登録する。
- iPhoneでは入力欄の「テキストをスキャン」で、表紙・奥付の文字を入力できる（OS標準機能のため実装は不要）。
- 「奥付を読む」ボタンで既存の文字認識（Tesseract・日本語）を使う。認識した行をタップして「書名」「サークル」「著者」に振り分け、そのまま検索する。横書きの奥付を想定する。表紙の装飾文字や縦書きは精度が低い。
- 文字認識の準備（初回約13MB）は既存OCR画面と共用し、二重に取得しない。

### 3.3 手入力

書名だけで登録できる。著者・サークル・発行日・メモは任意。後から書誌IDを紐づけられる（納本前の同人誌など）。

### 3.4 重複の検知

原則として1冊しか持たない運用のため、次の場合に登録前に警告する。登録自体は止めない。

- 所持中の蔵書とISBNまたは国立国会図書館の書誌IDが一致する。
- 正規化した書名（全角・半角、空白、記号の差を除く）と著者・サークルが一致する。
- 手放した本と一致する場合は「以前手放した本です」と表示する。

警告にはシリーズと置き場所を併記し、同じシリーズの既刊も確認できるようにする。

## 4. データ（NASのSQLite）

IDは端末でUUIDを生成する。各行に`revision`と`updated_at`を持つ。

| テーブル | 主な項目 |
| --- | --- |
| `bibs`（書誌） | id、isbn13（任意）、ndl_bib_id（任意）、書名、書名よみ、著者、サークル／出版者、発行日、シリーズ名候補、取得元、取得日時、利用者による上書き項目 |
| `series` | id、名称、著者・サークル、メモ |
| `copies`（蔵書） | id、bib_id、series_id、巻の並び順（数値）、巻表記（例：「総集編」「上」）、形態（紙／電子）、place_id（未設定可）、読書状態（未読／読書中／読了）、入手日・入手先・価格（いずれも任意）、処分（所持／売却／譲渡／廃棄）と処分日、メモ |
| `loans`（借用） | id、bib_id、借りた先、借りた日、返却期限、延長回数、返却日、読書状態、メモ |
| `places` | id、parent_id、名称、並び順、メモ |
| `operations` | 受付済み操作のUUID・内容・受付時刻・結果。削除しない。 |
| `covers` | bib_idまたはcopy_id、取得元、縮小画像のパス、更新日時 |
| `sheets_outbox` | Sheetsへ未反映の操作、試行回数、最終エラー |

- 書誌の上書き：利用者が修正した項目は、書誌を再取得しても上書きしない。
- 処分した蔵書：削除せず通常一覧から隠す。重複の検知に使う。
- 入手情報の価格は記録用で、家計簿とは連携しない。

## 5. 書誌の取得

問い合わせはNASから行い、結果を`bibs`に保存する。PWAに外部APIのキーを置かない。

| 順 | 取得元 | 用途 |
| --- | --- | --- |
| 1 | 国立国会図書館サーチ（SRU／OpenSearch） | 和書・納本済み同人誌。ISBN検索と書名・著者・出版者での検索。書誌IDを保存する。 |
| 2 | 楽天ブックス／楽天Kobo API | 新刊・流通中の本の補完、表紙画像。applicationIdとaccessKeyはNASの秘密値に置く。 |
| 3 | Google Books API | 洋書の補完。 |

- 一度取得した書誌は再取得せずに返す。共通設定から個別に再取得できる。
- 取得元ごとに間隔の制限と短い待ち時間を設け、失敗時は次の取得元へ進む。
- openBD v1は提供終了が告知されているため使わない。Amazonは使わない（PA-APIは2026年5月に廃止され、後継のCreators APIはアソシエイト登録が前提）。
- 各取得元の利用条件と出典の表示方法は、実装時に最新版を確認する。

## 6. 表紙

- 表示は共通設定の一括切替えで行う。オフの間は画像を一切読み込まない。
- オンのときは、画面に入った行だけ読み込む（`loading="lazy"`）。
- NASが元画像を一度だけ取得し、長辺120px程度の縮小画像（1枚数KB）を保存して配信する。端末は外部サイトに接続しない。
- 画像は端末のオフライン保存（IndexedDB・Service Workerのキャッシュ）に入れない。Sheetsにも入れない。
- 画像がない本は、撮影した表紙を端末内で長辺240px以下に縮小してから送れる。

## 7. API

`/api/library/`以下に置く。認証はBearer（本人用キー）。許可するOriginは完全一致で指定し、Cookieは使わない。応答は`Cache-Control: no-store`にする。

| メソッド・パス | 内容 |
| --- | --- |
| `GET /info` | `protocol: 1`、`mode: "library"`、サーバー版数 |
| `GET /snapshot?since=` | 蔵書・借用・置き場所・シリーズ・書誌の差分（初回は全件） |
| `POST /commands` | UUID付き操作の受付。同じUUIDの再送には前回の結果を返す。 |
| `GET /lookup?isbn=` ／ `GET /lookup?q=` | 書誌の取得・候補の検索（§5） |
| `GET /cover/{bib_id}` | 縮小した表紙画像 |
| `POST /cover/{copy_id}` | 撮影した表紙の登録（縮小済みの画像のみ受け付ける） |

主な操作：`copy.create`／`copy.update`／`copy.dispose`／`copy.restore`、`copies.move`（一括移動）、`series.create`／`series.update`／`series.merge`、`place.create`／`place.rename`／`place.move`／`place.merge`／`place.delete`（空のみ）、`loan.create`／`loan.renew`／`loan.return`／`loan.update`、`bib.override`。

## 8. 端末保存と同期

- IndexedDBに専用の保存領域を作る。日用品・家計簿・ニュース・OCRの保存領域には触れない。
- 操作は送信前にUUIDと編集開始時のrevisionとともに保存する。応答が失われた場合も同じUUIDで再送する。
- Web Locksで複数タブの送信を直列化する。非対応環境では保存を止めて案内を出す。
- 新規登録のIDは端末で確定するため、オフラインで「置き場所を作る→そこへ蔵書を登録する」と続けても順に送れる。
- 競合は自動で上書きしない。端末の入力を保持し、NASの値と並べて選ばせる。
- 到達の確認は日用品と同じ契機（起動・画面復帰・オンラインイベント・表示中60秒ごと）で行う。
- API応答とキーはService Workerの静的キャッシュに入れない。

## 9. Sheetsへのミラー

- 他のシステムから独立したスプレッドシートを使う。年などの区切りは設けない。
- シートは「蔵書」「借用」「置場」「シリーズ」「書誌」「操作履歴」の6枚。
- NAS→Sheetsの片方向とする。Sheetsでの編集はDBに戻さない。
- NASが操作を受け付けた後、`sheets_outbox`を通じて反映する。失敗した操作は再試行し、未反映件数をPWAに報告する。家計簿の反映方式を移植する。
- 各シートにはUUIDを含む全項目を書き出し、Sheetsから新しいDBを作り直せる形にする。復元用スクリプトと手順を同時に用意する。
- 「操作履歴」は追記のみとする。

ミラーはNASのディスクやDBが壊れたときの復旧元になる。一方で、誤操作やバグによる削除・上書きもそのまま反映される。誤操作からの復旧には操作履歴を使う。これとは別に、NAS側でSQLiteの定期バックアップを取る。

## 10. projectLivreとの連携（将来）

- 書誌のISBN13（正規化済み）と国立国会図書館の書誌IDを照合の鍵にする。
- `external_refs`（種類、外部ID、URL）を後から追加し、既存テーブルは変更しない。
- Calibreの`metadata.db`（`identifiers`テーブル）を読み取り専用で定期的に照合し、「Livreに電子版あり」の印とcalibre-webの書籍ページへのリンクを付ける。
- 同人誌の電子版をLivreに置く場合は、蔵書（形態：電子）と紐づける。

## 11. 実装構成

| 区分 | 内容 |
| --- | --- |
| NASサービス | `services/library/`（Python標準ライブラリ＋SQLite、Compose）。`services/news`と同じく、秘密値は`.secrets/`、許可Originは`.env`に置く。初期のbindは`127.0.0.1`。 |
| 画面 | `scripts/modules/libraryModule.js`（入口）、`libraryStore.js`（IndexedDB・送信待ち）、`libraryTransport.js`（API）、`libraryView.js`（4画面）、`library/fragment.html`、`styles/library.css`。家計簿と同じくShadow DOMで分離する。 |
| スキャン | `janScanner.js`の挙動は変えない。ISBN判定・重複抑止・連続読取りは`libraryScan.js`に置く。 |
| 文字認識 | `ocrModule.js`は認識処理を外部に公開していないため、エンジン部分を`ocrEngine.js`へ切り出し、OCR画面と本機能で共用する。OCR画面の挙動と`test:ocr`は変えない。 |
| 登録 | `app-config.js`の`features`と`shellFiles`に追加する。版数は1.13.0。 |

4画面は一つのモジュールとして同時に出す。置き場所・書誌・シリーズを蔵書と借用が共有するため、分けて出すと保存形式の移行が増える。

## 12. 検証

`tests/library.mjs`で合成のライブラリAPIを起動し、次を確認する。実NAS・実Google・外部の書誌APIには接続しない（書誌取得は合成応答を使う）。

- 4画面の切替え、見出しと画面内メニューの維持、下書きの保持。
- 連続スキャン：ISBNの判定、192／191の無視、5秒以内の重複抑止、まとめて登録。画像入力での代替。
- 圏外での登録→再接続で書誌が埋まる。同じUUIDで再送しても重複しない。
- 重複の警告（ISBN・書誌ID・正規化した書名・手放した本）。
- 借用：期限の計算（2週間・1か月・日付指定）、期限切れ・3日以内の強調、延長、返却、履歴。
- 置き場所：入れ子の作成、親の付替えで配下の所在が変わる、統合、空でない置き場所の削除拒否、一括移動。
- 表紙：オフのとき画像の通信が0件。オンのとき画面内だけ読み込む。
- 2タブの同時入力、編集中の他端末更新に対する上書き拒否。
- キーの永続保存なし、幅320〜390pxで横はみ出しなし、未捕捉のJS例外0。
- NAS側：Sheets反映の再試行、Sheetsからの復元スクリプトで同じ件数・内容に戻る。
