# 天気予報くんの連携

対象：v1.10.0／更新日：2026-11-12

「生活 → 天気予報くん」に、地域の天気予報と雨雲レーダーを同時に表示する。既存のHTML版で使われていた外部APIとWorkerをmini-appに組み込む。天気用のNAS APIを追加する構成ではなく、日用品・衣類の接続先・保存先・同期仕様は変更しない。

## 表示と操作

- 予報地域は東京23区・神奈川・千葉・埼玉・大阪・札幌・福岡。初回は東京を選択する。
- 初回の地図は地域の代表地点を使う。初回表示やメニュー切替で位置情報の許可を求めない。
- 「現在地を使用」を押したときに位置情報を取得し、その地点へ地図を移動する。地点別雨量が有効なら、設定されたWorkerへ緯度・経度を送って雨量を取得する。
- 前回地点の座標はこの端末に保存し、次回の地図で「前回の現在地」として再利用する。地図・雨雲提供元には、その表示範囲に対応するタイルを要求する。一方、開き直した直後はWorkerへ座標を送らず、再度「現在地を使用」を押した後に地点別雨量の取得・更新を開始する。
- 表示範囲は**中心から半径2km（直径4km）**の円。正方形の地図内に円全体が入る縮尺へ合わせ、「半径2kmに戻す」で表示を戻す。画面幅や余白によって円の外側も表示する。
- 雨雲は実況・予測を時刻付きで表示し、時刻スライダー、再生・停止、濃さの変更に対応する。
- 地図の拡大は元の雨雲画像の拡大表示であり、元データより細かい降水分布を生成しない。
- 960px未満では予報と雨雲を縦並び、それ以上では横並びにする。操作ボタンは既存のグレー・角丸なしを維持する。

位置情報を利用できない場合も、選択地域の予報と代表地点の雨雲を確認できる。最新の情報が得られない場合は取得状態や前回値の日時を確認する。

## 情報提供元

| 対象 | 取得先 | 備考 |
| --- | --- | --- |
| 地域別予報 | `https://weather.tsukumijima.net/api/forecast?city=…` | 今日・明日・明後日の天気、予想気温、降水確率、概況。地域を表すIDを送信する。 |
| 雨雲の時刻 | 気象庁 `https://www.jma.go.jp/bosai/jmatile/data/nowc/targetTimes_N1.json`、`targetTimes_N2.json` | 実況と予測の時刻・基準時刻を取得する。 |
| 雨雲画像 | 気象庁 `https://www.jma.go.jp/bosai/jmatile/data/nowc/{basetime}/none/{validtime}/surf/hrpns/{z}/{x}/{y}.png` | 指定時刻・表示範囲に対応する画像を地図へ重ねる。 |
| 背景地図 | `https://tile.openstreetmap.org/{z}/{x}/{y}.png` | 表示中の範囲を取得する。一括取得やオフライン地図作成は行わない。 |
| 地点別雨量 | 利用者が設定したHTTPSのWorker | `lat`・`lon`を送り、JSONまたはYDF XMLの `Weather` にある `Date`・`Rainfall`・`Type` を使用する。 |

地図ライブラリはLeaflet 1.9.4を同梱する。地図・雨雲の画像は外部配信のため、ライブラリを同梱していても通信が必要になる。

## 地点別雨量の設定

画面下部の「地点別雨量の設定」で接続先を保存する。初期値は従来のHTML版と同じ `https://flat-bush-0140.kamimai2033.workers.dev/`。空欄で保存すると地点別雨量だけを停止し、地域別予報と雨雲レーダーは引き続き利用できる。

接続先はHTTPSで、mini-appの配信元からブラウザーで呼び出せる必要がある。Worker内のAPIキーをmini-appへ埋め込まない。接続先変更後は、その提供元へ表示地点の緯度・経度が送られることを確認する。設定は端末ごとに保存される。

従来WorkerはHTTPのContent-TypeがJSONでも、本文にYDF XMLを返す場合がある。そのため、本文を確認してJSONまたはXMLとして読み、共通の表示形式に変換する。名前空間付きXMLに対応し、DOCTYPEを含むXML・構文エラー・雨量データがない応答は取得失敗として扱う。雨量の空白・欠測・負の値を降雨量0として表示しない。

## 通信・保存・失敗時の扱い

| 対象 | 保存・更新の扱い |
| --- | --- |
| 地域・Worker接続先・前回地点 | 端末に保存する。他端末やNASへ設定を同期しない。前回地点は地図に使うが、開き直した後のWorker送信は現在地ボタンで再開する。 |
| 地域別予報 | 15分の短期キャッシュで繰り返し取得を抑える。前回取得したテキストを端末に保存する。 |
| 地点別雨量 | 前回取得したテキストを端末に保存する。取得失敗時に前回値を最新値として扱わない。 |
| 地図・雨雲画像 | ブラウザーの通常のHTTPキャッシュを利用できるが、アプリによるオフライン保存は保証しない。 |
| 予報・雨雲・地点別雨量の障害 | それぞれ状態を表示する。一つの取得失敗で他の機能を使えなくしない。 |

予報の気温などには未発表・欠測を表すnullが含まれる。欠けた値を0℃や降水なしと解釈しない。オフラインや通信失敗時に前回のテキストが表示できても、それは現在の天気を保証するものではない。

## 静的配信の更新

1. v1.10.0の検査を通した同じコードから`npm run build:deploy`で配信用ファイルを生成する。
2. `dist/`の中身、またはその内容を反映した`deploy`を、従来と同じHTTPSのオリジン・配信パスへ配置する。Leafletを含め、生成した一式を配置する。
3. アプリの新版準備表示を確認し、すべてのタブ・PWAウィンドウを閉じて開き直す。表示バージョンがv1.10.0になったことを確認する。
4. 天気の確認に加え、日用品・衣類の接続設定と取得済みデータが引き継がれていることを確認する。

オリジンは方式・ホスト名・ポートの組合せ。別オリジンへ移すと、従来の端末保存データをそのまま共有できない。更新確認のためにブラウザーのサイトデータを消去しない。

## 配備後の確認

- 初回表示で位置情報の許可要求が出ず、地域別予報と代表地点の雨雲が表示される。
- 現在地を許可した場合に中心が移動し、半径2kmの円全体が収まる。拒否した場合も他の表示を続けられる。
- 拡大後に「半径2kmに戻す」で戻り、時刻・再生・濃さの各操作が動作する。
- Workerの雨量取得、接続先変更、空欄による無効化、通信失敗時の表示が動作する。
- 地点別雨量の取得後に開き直すと、前回地点・前回雨量を表示しながらWorkerへの自動送信は行わず、再度の現在地操作で取得を再開する。
- WorkerがJSONを返す場合と、JSONのContent-TypeでYDF XMLを返す場合の両方を処理できる。
- 320px幅で横にはみ出さず、広い画面では予報と雨雲が同時に見える。
- オフライン時は前回テキストと取得状態を区別でき、雨雲取得失敗を「雨なし」と表示しない。
- 同じ配信元への更新後も日用品・衣類の設定・送信待ちが保たれる。バックアップ復元試験は通常更新と分けて行う。

自動検査とiPhone・実配信先での確認は区別する。この一覧は配備後の確認項目であり、文書を追加した時点で実機確認済みを意味しない。

## 予報APIを本番運用する際の確認

この試用版は既存HTMLと同じブラウザー直接取得を維持する。TsukumijimaはCORSを許可する一方、テスト・開発以外の利用にはアプリを識別する独自User-Agentを求めている。ブラウザーによっては`fetch`で指定したUser-Agentを無視するため、ヘッダーを追加するだけではこの要請を満たしたと扱えない。継続的な本番利用では、提供者への確認、または識別用ヘッダーを設定できる取得経路を別途検討する。現版に天気用NAS APIを追加することは前提にしない。

根拠：[Tsukumijimaの利用案内](https://weather.tsukumijima.net/)、[ブラウザーのリクエストヘッダー制約](https://developer.mozilla.org/en-US/docs/Glossary/Forbidden_request_header)。

## 出典・利用条件

- [Tsukumijima Weather API](https://weather.tsukumijima.net/)：気象庁データをJSON形式にした非公式API。CORS対応、連続アクセスは0.5秒以上空ける。ブラウザーからの利用を想定し、短期キャッシュと更新操作で不要な取得を抑える。
- [気象庁「高解像度降水ナウキャスト」](https://www.jma.go.jp/jma/kishou/know/kurashi/highres_nowcast.html)：雨雲データの説明。画面の縮尺と元データの分解能は別として扱う。
- [気象庁ホームページの利用条件](https://www.jma.go.jp/jma/kishou/info/coment.html)：出典を示し、拡大・地図との重ね合わせを行う旨を表示する。
- [OpenStreetMapのタイル利用方針](https://operations.osmfoundation.org/policies/tiles/)：地図上の帰属表示、通常のHTTPキャッシュとRefererを維持し、先読み・一括保存を追加しない。
