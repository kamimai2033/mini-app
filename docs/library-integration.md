# 本棚・図書館の連携

v1.13.0。「生活」メニューの末尾から開く。NAS側に [kamimai2033/libre_integration](https://github.com/kamimai2033/libre_integration)（Library API 0.1.0、protocol 1）が必要。計画時の検討内容は[更新計画](plans/library-integration.md)にある。

## 画面

画面内メニューは「蔵書管理／借用管理／置場管理／共通設定」（各4文字）。4画面は一つのモジュール・一つのShadow DOMで構成し、切り替えても見出し・メニュー・送信待ち・登録中の一覧を維持する。

| 画面 | 内容 |
| --- | --- |
| 蔵書管理 | 登録（連続スキャン・ISBN入力・書名検索・書名だけで追加）、シリーズごと／1冊ずつの一覧、検索（書名・よみ・著者・サークル・ISBN・メモ・入手先・シリーズ）、読書状態・置き場所（配下を含む）・形態の絞込み、手放した本の表示切替え。詳細画面で書誌の修正・再取得、シリーズと巻、置き場所、読書状態、入手情報、価格、メモ、手放す／所持に戻す。シリーズの名前変更と統合。 |
| 借用管理 | 借りた先・借りた日・貸出期間（2週間／1か月／日付を指定）を決めてから登録。未返却を返却期限の近い順に表示し、期限切れと残りN日以内（既定3日）を強調。返却・返却の取消し・延長（手続き日から数える）・編集。返却済みは「返却済みを表示」で閲覧。 |
| 置場管理 | 入れ子の置き場所の追加・名前変更・移動（箱ごと）・統合・削除（空の場合のみ）。配下を含む冊数、場所未設定の冊数。移動元を選んでチェックした本をまとめて移動。移動先を選んで読み取った本を順に移す移動スキャン。 |
| 共通設定 | 接続先とアクセスキー、表紙表示の一括切替え（既定はオフ）、期限を強調する日数、書誌の取得状況と再検索、送信待ち（競合の上書き・破棄、取消し）、端末データの書き出し。 |

## 登録

- 連続スキャン：`janScanner.js` は停止するまで読取りを返すので、`libraryScan.js` が次を判定する。978／979で始まりチェックディジットが正しいコードだけをISBNとして採用し、書籍JANの下段（191／192）は無視する。同じコードを5秒以内に読んだ場合は無視し、採用時に短い音を鳴らす。
- 読取済み一覧：同じISBNは二重に追加しない。所持中・手放した本・返却前の借用と一致する場合は警告を表示する（ISBN、国立国会図書館の書誌ID、正規化した書名＋著者で照合）。登録は止めない。
- 書誌：接続中はNAS経由で取得する（国立国会図書館サーチ → 楽天ブックス → Google Books）。NASに届かない場合はISBNだけで登録し、送信後にNASが書誌を埋める。見つからない本は一覧で書名を入力できる。
- 同人誌：書名・著者／サークルで国立国会図書館サーチを検索し、候補から選ぶ。ISBNがなくても書誌IDで識別する。検索に出ない本は「書名だけで追加」。iPhoneでは入力欄の「テキストをスキャン」で表紙・奥付の文字を入力できる。
- 巻：国立国会図書館の巻情報、またはシリーズ指定時の書名末尾の数字から巻表記と並び順を補う。一覧で修正できる。
- 新しいシリーズを作って登録した後は、そのシリーズが次の登録の初期値になる（同じ名前のシリーズを重ねて作らない）。
- 登録中の一覧と条件は端末に保存し、再読込み後も残る。入力中の欄は、背景の同期や書誌取得で作り直さない。

## 接続と端末保存

接続先はHTTPSのOriginだけを入力する（localhostだけHTTP可）。`/api/library/info` で protocol=1・mode=library を確認してから、本人用アクセスキーをBearerで送る。Cookieは送らず、キーはメモリー内だけに保持する。再読込み後は再入力が必要だが、端末のデータ・送信待ち・登録中の一覧は残る。

IndexedDB `mini-app-library:<配信パス>:v1` に、接続先ごとのデータ（置き場所・シリーズ・書誌・蔵書・借用）、送信待ち、表示設定、登録中の一覧を保存する。日用品・家計簿・ニュース・OCRの保存領域には触れない。API応答とキーはService Workerの静的キャッシュに入れない。

初回はNASへ接続してNASの識別情報（server_id）を取得する必要がある。以後は圏外でも登録・編集・移動ができ、送信待ちに入る。

## 同期と競合

- 操作は送信前にUUIDとともに保存する。応答が失われても同じUUIDで再送し、NASは同じ結果を返す（重複しない）。
- 送信は1回50件まで、キューの順に送る。その後 `snapshot?since=<cursor>` で差分だけを取得する。NASのデータが巻き戻っていた場合（cursorが先行）は全件を取り直す。
- 更新系の操作は編集開始時のrevisionを送る。NAS側で先に変更されていれば「競合」として送信待ちに残り、NASの最新値を表示する。共通設定で「自分の変更で上書き」（新しいUUIDで最新revisionに対して再送）か「破棄」を選ぶ。自動では上書きしない。
- 端末の表示は、NASのデータに送信待ちの操作を重ねたもの。新規の本・置き場所もすぐ一覧に出る。
- Web Locksで複数タブの同期を直列化し、BroadcastChannelで他のタブに変更を知らせる。同期は起動・画面表示・オンライン復帰・フォーカス時と、表示中の60秒ごとに行う。

## 表紙

共通設定の一括切替えで表示する（既定はオフ）。オフの間は表紙の通信を一切行わない。オンのときは画面に入った本の分だけ、NASの `/api/library/cover/<書誌ID>` からBearer付きで取得し、そのページを開いている間だけメモリーに保持する。端末のオフライン保存には入れない。NASは楽天ブックス（128px）またはGoogle Booksの小さい画像を一度だけ取得して保存する。

## NAS側

構成・設定・APIの詳細は libre_integration の README と `docs/api.md` を参照する。要点：

- Python標準ライブラリ＋SQLite。Compose、秘密値は `.secrets/`、許可Originは `.env`。初期bindは `127.0.0.1:8020`。
- 楽天ブックスAPIは2026年の新しい接続先（`openapi.rakuten.co.jp`）を使い、applicationIdとaccessKey（ヘッダー）が必要。未設定なら楽天を使わない。
- 国立国会図書館サーチの書影APIは仕様書（第1.4版）で削除されたため使わない。

## 検証

- `npm run test:library-core`：ISBN判定、期限計算（2週間・1か月の月末処理・東京の日付）、送信待ちを重ねた表示、重複判定、巻の並び。NAS不要。
- `npm run test:library`：`LIBRARY_API_ROOT` に libre_integration のチェックアウトを指定すると、実API＋一時SQLite＋外部書誌のfixtureで画面を操作して検査する。`LIBRARY_API_PYTHON` で Python を指定できる。指定がなければSKIPする。libre_integration側のCIでも同じ検査を実行する。

2026年11月26日、Linux上のChromium（Playwright）で次を確認した。

- 初回の明示的な接続、誤ったキーの拒否、Cookieなし。
- 入れ子の置き場所、ISBN入力（下段コードの拒否・重複行の抑止）と国立国会図書館の書誌、置き場所付きの登録。
- 書名検索（ISBNなしの同人誌・書誌ID）、新しいシリーズ、巻の補完、シリーズごとの表示と巻順。
- 所持中・手放した本の重複警告、書誌の修正（再取得しても保持）、他端末の変更との競合と明示的な上書き。
- NASに届かない状態での借用登録 → 再接続後の送信 → NASによる書誌の補完。期限切れの強調と並び順、返却・取消し・延長。
- まとめて移動、箱の統合、空でない置き場所の削除拒否、手放した本の表示切替え。
- 表紙は既定で通信なし、オンのときだけ取得。
- 幅320px・390pxで4画面とも横はみ出しなし。
- オフラインでの再起動後もデータと登録中の一覧が残り、登録は送信待ちになり、再接続で送信される。アクセスキーは保存されない。未捕捉のJS例外0。
- 既存の `npm test`・`test:inventory`・`test:weather`・`test:news`・`test:deploy` も `dist/` で通過。

カメラでの連続読取りとiPhone実機での表示・HTTPS接続は、NASへの配備後に確認する。
