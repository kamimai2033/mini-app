# 生活メニューの画面仕様

確定日：2026-11-09／天気仕様更新：2026-11-12

画面の階層・名称・配置を定義する。日用品・衣類連携はv1.9.0、天気予報と雨雲の連携はv1.10.0で実装。

## 階層と名称

| 階層 | 位置・表示条件 | 項目・見出し | 文字数 |
| --- | --- | --- | --- |
| 上部ナビゲーション | 共通ヘッダー | 生活 | 2 |
| 展開メニュー | 「生活」を開いたとき | アドレス生成／天気予報くん／日用品・衣類 | 各6 |
| 機能の見出し | 「日用品・衣類」を選択した画面の上部 | 日用品・衣類 | 6 |
| 画面内メニュー | 機能の見出しのすぐ下 | 日用管理／衣類管理／通知履歴／共通設定 | 各4 |
| 本文 | 画面内メニューの下 | 選択した管理画面の内容 | — |

「生活」の展開メニューの並び順は、アドレス生成、天気予報くん、日用品・衣類とする。
「日用管理」「衣類管理」「通知履歴」「共通設定」は、「日用品・衣類」の内部で切り替える項目とする。

## 日用品・衣類の画面

上から次の順序で配置する。

1. 共通ヘッダーと上部ナビゲーション。
2. 現在の機能を示す見出し「日用品・衣類」。
3. 画面内メニュー「日用管理」「衣類管理」「通知履歴」「共通設定」。
4. 選択中の管理画面の見出しと本文。

画面内メニューで切り替えても、「日用品・衣類」の見出しと4項目は表示を維持する。
選択中の項目を視覚的にも支援技術でも判別できるようにする。
初回の表示先は「日用管理」を基本とする。切替時に未保存の入力や送信待ちの操作を失わせない。
別の機能へ移動したときは、この画面内メニューを非表示にする。

| 画面内メニュー | 機能の範囲 |
| --- | --- |
| 日用管理 | 日用品の商品・購入履歴・棚卸し・在庫予測を扱う。 |
| 衣類管理 | 衣類の種類・商品・個体別の状態・期限・延期を扱う。 |
| 通知履歴 | 日用品・衣類の通知履歴と送信状態、通知チェックを扱う。 |
| 共通設定 | 接続・同期状態・送信待ちの確認、バックアップ・復元などの共通操作を扱う。 |

操作ごとのオンライン・オフライン動作とAPIの詳細は[連携仕様](inventory-integration.md)を参照する。

## 天気予報くん

「生活」の展開メニューから独立した機能として開く。日用品・衣類の画面内メニューには含めない。
天気予報と雨雲レーダーを同じ画面に同時に載せる。
スマホでは縦並び、960px以上の画面では横並びとし、どちらか一方だけを表示する切替タブにはしない。

- 予報側は地域選択、更新操作、取得状態、今日・明日・明後日の予報を配置する。
- 雨雲側は現在地の利用、表示範囲のリセット、更新操作、表示地点、正方形の地図、時刻・再生・濃さの操作、地点別雨量を配置する。
- 表示範囲は中心から半径2km（直径4km）の円を基本とし、円全体が入るように画面幅へ合わせる。「半径2kmに戻す」で拡大・移動後の表示を戻す。
- 初回は東京の代表地点を使い、位置情報の許可を求めない。「現在地を使用」を押したときだけ現在地を取得する。
- 前回地点は端末に保存し、次回の地図で「前回の現在地」として再利用する。開き直した後の地点別雨量取得は、再び「現在地を使用」を押すまで開始しない。
- 画面下部の折りたたみ設定で、地点別雨量のHTTPS接続先を変更する。空欄で保存した場合は地点別雨量を停止する。
- 予報・雨雲・地点別雨量の状態を分けて表示し、一つの取得に失敗しても他の表示を妨げない。

情報提供元・通信・保存・更新の仕様は[天気の連携](weather-integration.md)を参照する。NAS用の天気APIを新設する構成ではない。

## 表示方針と確認事項

- 各メニューの中で文字数を揃える。上部は原則2文字、今回の生活メニューは6文字、管理画面内は4文字とする。
- 名称は表のとおりに使い、「天気予報くん」を「天気予報」、「日用品・衣類」を別の名称に省略しない。
- 既存の配色・配置を基本とし、操作ボタンは標準グレー・角丸なしを維持する。
- 画面内メニューは見出しのすぐ下に置く。同期情報や入力フォームは、その下の本文側に置く。
- スマホでは必要に応じてメニューを折り返し、文字や操作領域のはみ出し・重なりを防ぐ。
- マウス・タッチ・キーボードで各機能と管理画面を切り替えられることを確認する。
- 管理画面を切り替えても、共通見出しと4項目が残ることを確認する。
