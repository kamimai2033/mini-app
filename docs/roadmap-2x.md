# 2.xに向けた更改案（未着手）

既存の軽さと従来の画面を保ちながら、複数のNASサービスを扱える共通基盤へ更改する。機能追加だけの1.x更新と区別し、以下をまとめて2.0.0の候補とする。

日用品・衣類はv1.9.0、天気予報と雨雲の同時表示はv1.10.0で実装済み。天気は既存の外部APIとWorkerを使う。以下は、これらの実装を踏まえた共通化・拡張の候補であり、天気機能の初回実装を2.xまで待つ計画ではない。

| 更改対象 | 2.xで目指すこと |
| --- | --- |
| 共通の接続・保存・同期 | 日用品・衣類、天気、将来のローカル辞書等の接続設定・到達状態・更新時刻を一か所で管理。サービスごとの障害を分離する。 |
| PWAの導入・更新・復旧 | 初期導入で必要データを検査。更新前の退避、保存形式の移行、復旧時の端末データ取込みを整備し、配信停止後の運用を標準化する。 |
| 機能の登録方式 | 機能ID、表示名、階層、必要ファイル、保存形式、通信条件を宣言する共通仕様。機能を足す際にメニュー・キャッシュ・画面を別々に直す作業を減らす。 |
| 天気の運用整理 | v1.10.0の予報・雨雲・地点別雨量について、接続状態・取得日時・前回値の扱いを共通基盤へ統合。情報提供元の変更にも対応できるようにする。 |
| 利用者向け運用画面 | 接続診断、保存容量、各機能の準備状態、未送信件数、復旧手順を一画面で確認できるようにする。 |

Reactへの移行や見た目の刷新を目的にはしない。HTML／CSS／ES Modulesで継続可能。共通化は、日用品・衣類と天気の両方で必要と分かった部分から行う。

着手順：1.xで日用品・衣類と天気の実機運用を確認 → 共通化する接続状態・保存仕様を確定 → 保存形式の移行手順を設計 → 2.0の試用版で更新／復旧を検証 → 正式移行。バックアップからの復元は、データと試験手順を別途確認して実施する。

2.0への移行条件：旧版からのデータ移行、送信待ちを失わない更新、API停止時の切替、配信停止後の起動・復旧、320px幅とiPhone実機の操作を確認する。

## 追加機能の検討候補

家計簿とRSSは今後の検討候補。実装範囲や導入時期は未確定で、v1.10.0には含めない。小規模な機能追加なら1.xで先行し、共通基盤の更改が必要な部分を2.xで扱う。

| 候補 | 次に整理する事項 |
| --- | --- |
| 家計簿 | 既存NASサービスへの入口・閲覧・入力のどこまでをmini-appで扱うか。利用できるAPI、認証、更新の競合、保存・バックアップ範囲を確認する。 |
| RSS | 購読先の登録、記事一覧、既読管理、取得頻度、オフライン時に保持する範囲を決める。取得元のCORS条件を確認し、必要な場合のみ中継方式を検討する。 |
