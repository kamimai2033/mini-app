# 2.xに向けた更改案（未着手）

既存の軽さと従来の画面を保ちながら、複数のNASサービスを扱える共通基盤へ更改する。機能追加だけの1.x更新と区別し、以下をまとめて2.0.0の候補とする。

| 更改対象 | 2.xで目指すこと |
| --- | --- |
| 共通の接続・保存・同期 | 日用品・衣類、天気、将来のローカル辞書等の接続設定・到達状態・更新時刻を一か所で管理。サービスごとの障害を分離する。 |
| PWAの導入・更新・復旧 | 初期導入で必要データを検査。更新前の退避、保存形式の移行、復旧時の端末データ取込みを整備し、配信停止後の運用を標準化する。 |
| 機能の登録方式 | 機能ID、表示名、階層、必要ファイル、保存形式、通信条件を宣言する共通仕様。機能を足す際にメニュー・キャッシュ・画面を別々に直す作業を減らす。 |
| 天気の統合 | 別システムのAPIを利用し、予報と雨雲レーダーを同じ画面に表示。両方の取得日時・オフライン状態を明示する。 |
| 利用者向け運用画面 | 接続診断、保存容量、各機能の準備状態、未送信件数、復旧手順を一画面で確認できるようにする。 |

Reactへの移行や見た目の刷新を目的にはしない。HTML／CSS／ES Modulesで継続可能。共通化は、日用品・衣類と天気の両方で必要と分かった部分から行う。

着手順：1.xで日用品・衣類の実機運用を確認 → 天気APIを確定 → 共通機能・保存形式の移行手順を設計 → 2.0の試用版で更新／復旧を検証 → 正式移行。

2.0への移行条件：旧版からのデータ移行、送信待ちを失わない更新、API停止時の切替、配信停止後の起動・復旧、320px幅とiPhone実機の操作を確認する。
